## 1. アプリの全体像（前提情報）

このアプリは**カップルが結婚式の準備タスクを管理するためのスマホアプリ**で、以下の3つの部品でできています。

```
[ カップル / プランナー ]
        │
        │  LINE LIFF（LINEのアプリ内ブラウザ）
        ▼
[ フロントエンド: Next.js (React) ]   ← 画面表示を担当
        │
        │  HTTPS（暗号化通信）
        ▼
[ バックエンド: Google Apps Script ]  ← データ処理を担当
        │
        ├─→ Google Sheets（データベースの代わり）
        ├─→ LINE Messaging API（LINE通知送信）
        └─→ Anthropic Claude API（AIメッセージ自動生成）
```

### 🔤 用語解説

- **LIFF（リフ）**: LINEが提供する公式の仕組み。LINEアプリの中でWebサイトを開くと、自動的にユーザーをLINEで認証してくれる。**自前でログイン画面を作らなくていい**のが大きな利点。
- **Next.js（ネクストジェイエス）**: Facebookが開発した「React」というUI部品ライブラリの上で動く、業界標準の有名なフレームワーク。世界中の有名サービス（TikTok、Hulu、任天堂など）で採用されている。
- **Google Apps Script（GAS）**: Googleが提供するサーバーサイドの実行環境。Googleスプレッドシートをデータベース代わりに使える。**Google社のセキュリティ基盤の上で動く**ため、サーバー単体のハッキングリスクが極めて低い。

## 2. セキュリティ観点別 詳細レビュー

### 2-1. 認証（あなたが本人かどうか確認する仕組み）  ✅ 良好

**何をしているか**: ユーザーは自前のパスワードを作りません。LINEの公式ログインを使い、「LINEの本人確認に成功した人だけ」が利用できる仕組みになっています（[useLiff.ts:38](src/hooks/useLiff.ts#L38)）。

**なぜ安全か**:
- パスワードがアプリ側に存在しないため、**「パスワードリスト流出」というリスクが構造的に発生しない**
- LINEは2段階認証や不正検知を備えた大規模認証基盤
- 一般的に「自前でパスワード管理する」より「Googleログイン・LINEログインを使う」方が安全（OAuth/OpenID Connect方式）

**🔤 用語解説 — OAuth（オーオース）**: 「家のカギ」を渡さずに「玄関を開ける専用カード」だけを渡す仕組み。たとえば「Twitter連携でログイン」と同じ方式。

---

### 2-2. 認可（誰が何を操作できるかの制御）  ✅ 概ね良好 ⚠️ 1件改善推奨

**何をしているか**:
- 一般カップル: 自分のタスクだけ表示・更新できる
- プランナー（式場担当）: 自分の式場のカップルのみ閲覧・操作できる
- 超管理者（is_admin）: すべての式場を操作できる

サーバー側（GAS）で `customer.venue_id` を取得し、URLパラメータより **データベース側の正しい所属を優先** している点は良い設計です（[Code.ts:25](gas/Code.ts#L25)）。

> ⚠️ **改善推奨事項①**: `line_id` パラメータが「リクエスト本文にユーザーが書いた値」をそのまま信頼しています（[Code.ts:14, 71](gas/Code.ts#L71)）。理論的には、悪意のあるユーザーが自分以外の `line_id` を送りつけて他人のデータを読む攻撃が成立する可能性があります（IDOR脆弱性と呼ばれます）。
>
> **🔤 IDOR（アイダー）**: Insecure Direct Object References。「URLの番号を変えたら他人の情報が見えた」型の脆弱性。
>
> **対策案**: GAS側で **LINEから発行されたID Tokenを検証** する処理を追加するのが王道です。LIFFの `liff.getIDToken()` を使い、サーバー側でLINEの公開鍵で署名検証を行えば、なりすましを防げます。

---

### 2-3. 通信の暗号化  ✅ 良好

**何をしているか**: すべての外部通信が **HTTPS（暗号化通信）** に固定されています。
- フロントエンド ↔ GAS: `https://script.google.com/...`（[api.ts:33,123](src/lib/api.ts#L33)）
- GAS ↔ LINE Messaging API: `https://api.line.me/...`（[reminders.ts:78](gas/reminders.ts#L78)）
- GAS ↔ Claude API: `https://api.anthropic.com/...`（[claude.ts:48](gas/claude.ts#L48)）

**なぜ安全か**: 通信経路でWi-Fiの盗み見をされても、内容が暗号化されているため意味を読み取れません（喫茶店のフリーWi-Fi対策として標準）。

---

### 2-4. 機密情報の管理（APIキー・トークン）  ✅ 良好

**何をしているか**:
- Claude APIキー → GASの **PropertiesService**（Googleの安全な設定保管庫）に保管（[claude.ts:14](gas/claude.ts#L14)）
- LINEチャネルアクセストークン → 同じく **PropertiesService**（[reminders.ts:60](gas/reminders.ts#L60)）
- ローカル開発用の `.env.local` は `.gitignore` で除外され、公開リポジトリに上がらない設定（[.gitignore:29](src/.gitignore#L29)）

**🔤 用語解説 — PropertiesService**: Google Apps Scriptが提供する「金庫」のような機能。値はGoogleのサーバー内で暗号化保管され、コードを見ても中身は分からない。

**なぜ安全か**: ブラウザ（クライアント）に秘密情報が一切渡らないため、利用者が開発者ツールを開いても、APIキーは見えません。

> ⚠️ **改善推奨事項②**: 管理者ログインのフォールバックで `process.env.NEXT_PUBLIC_ADMIN_PASSWORD || "roots2026"` というハードコードされたパスワード `"roots2026"` が残っています（[admin/page.tsx:92](src/app/admin/page.tsx#L92)）。
>
> しかも `NEXT_PUBLIC_*` で始まる環境変数は **Next.jsの仕様上ブラウザに配信される** ため、開発者ツールを開けば誰でも見えます。
>
> **対策案**:
> 1. パスワード認証はクライアント側で完結させず、GAS側で検証する
> 2. デフォルトパスワード `"roots2026"` を削除する（環境変数未設定時はログインを拒否する）
> 3. 認可は `is_admin` フラグの**サーバー側照合だけ**で行う（クライアント側のパスワード判定は飾りでしかない）

---

### 2-5. XSS（クロスサイトスクリプティング）防止  ✅ 良好

**🔤 用語解説 — XSS**: 攻撃者が悪意のあるJavaScriptを画面に埋め込み、訪問者のブラウザで勝手に動かす攻撃。代表例: クッキー（ログインの証明書）を盗んで他人になりすます。

**何をしているか**: 全ファイルを点検した結果、危険なAPI（`dangerouslySetInnerHTML`, `eval`, `document.write`, `innerHTML`）は **1箇所も使われていません**。

```bash
grep -rn "dangerouslySetInnerHTML|eval|innerHTML|document.write" src/
→ no matches （該当なし）
```

**なぜ安全か**: React は標準で「画面に表示する文字を自動でエスケープ（無害化）する」仕組みになっており、ユーザーが入力した文字（例: カップルの名前 `さくら`）は、たとえ `<script>` タグが入っていても、**ただの文字として表示される**だけでJavaScriptとして実行されません。

---

### 2-6. インジェクション攻撃（SQL/コマンド/その他）  ✅ 良好

**🔤 用語解説 — SQLインジェクション**: データベースに「DROP TABLE customers」のような不正な命令を紛れ込ませて、データを盗む・破壊する攻撃。

**何をしているか**: そもそも **SQLデータベースを使っていません**。データは Google Sheets にあり、GASの `SpreadsheetApp.getRange().setValue()` という型安全なAPIで読み書きしています（[sheets.ts:7-25](gas/sheets.ts#L7)）。

**なぜ安全か**:
- SQL構文を文字列連結で組み立てる箇所がゼロ → SQLインジェクション不能
- シェルコマンド実行（`exec`, `eval` 等）も使用していない → コマンドインジェクション不能
- `JSON.parse(e.postData.contents)` は標準の安全な解析（[Code.ts:65](gas/Code.ts#L65)）

---

### 2-7. URLからのファイル覗き見（パストラバーサル）  ✅ 良好

ファイルシステムを直接操作する処理は存在しません。すべてGoogle Sheets経由のデータアクセスなので、`../../etc/passwd` のような攻撃が原理的に成立しません。

---

### 2-8. 個人情報（PII）の取り扱い  ✅ 良好 ⚠️ 1件改善推奨

**保管しているデータ**:
- LINEユーザーID（`U00000...` 形式の匿名ID — 氏名・電話番号は含まない）
- カップルのお名前（ひらがな）
- 挙式日

**保管場所**: Google Sheets（Google社のセキュリティ基盤上、暗号化保管）

**🔤 用語解説 — PII**: Personally Identifiable Information（個人を特定できる情報）。日本の個人情報保護法でも保護対象。

> ⚠️ **改善推奨事項③**: 起動画面でAPIエラー発生時に、サーバーからの **生のエラーメッセージ** を画面に出力しています（[page.tsx:39-43](src/app/page.tsx#L39)）。
>
> 開発時は便利ですが、本番ではサーバー内部の構造（テーブル名、ファイルパス等）を漏らす可能性があります。
>
> **対策案**: 本番ビルドでは「通信エラーが発生しました」のような汎用メッセージに差し替える。

---

### 2-9. 依存ライブラリの安全性  ✅ 良好

**主要ライブラリ**（[package.json](src/package.json)）:
- `next` 14.2.35（Next.jsの安定版・サポート中バージョン）
- `react` 18系（業界標準・現役メジャーバージョン）
- `@line/liff` 2.28.0（LINE公式ライブラリ）

いずれも著名・現役メンテナンス中の正規ライブラリで、不審なライブラリの混入はありません。

---

### 2-10. クライアント側の保存データ（localStorage）  ✅ 軽微

ダッシュボードのキャッシュとして `localStorage` にタスク一覧を保存しています（[dashboard/page.tsx:63](src/app/dashboard/page.tsx#L63)）。

**評価**:
- 保存される内容は **本人のタスク一覧** のみ（他人のデータは入らない）
- 同じスマホの他のサイトからは読めない（ブラウザのオリジン分離）
- パスワードや決済情報は **保存されていない**
- 紛失時に深刻な被害を生むデータではない

→ リスクは限定的で、UX（オフライン体験向上）の利点が上回ります。

## 3. セキュリティ標準との対応関係

### 3-1. OWASP Top 10（世界的なWebセキュリティ脅威ランキング）対応状況

**🔤 OWASP Top 10**: 世界中のセキュリティ専門家団体OWASPが発表する「最も多いWeb脆弱性トップ10」。Webアプリの実質的なグローバル基準。

| OWASP 2021 | 脅威の概要 | 本アプリの状態 |
|-----------|----------|-------------|
| A01: アクセス制御の不備 | 他人のデータが見える等 | ⚠️ IDORの可能性（推奨①参照） |
| A02: 暗号化の不備 | 通信の盗聴 | ✅ HTTPS強制で対策済み |
| A03: インジェクション | SQL等の不正命令 | ✅ 構造的に発生不能 |
| A04: 安全でない設計 | 認証・認可の設計欠陥 | ✅ LINE OAuth方式で対策済み |
| A05: セキュリティ設定ミス | デフォルトパスワード等 | ⚠️ デフォルト管理者パスワード（推奨②参照） |
| A06: 脆弱なコンポーネント | 古いライブラリ | ✅ 主要ライブラリ最新世代 |
| A07: 認証の不備 | パスワード管理の弱さ | ✅ パスワードを自前で持たない設計 |
| A08: データの完全性不備 | 改ざん検知不足 | ✅ Google基盤の整合性に依存 |
| A09: ログ・監視の不備 | 攻撃検知不能 | ⚪ Google Cloud標準ログに依存 |
| A10: SSRF | サーバーが外部に乗っ取られる | ✅ 該当する処理が存在しない |

### 3-2. 個人情報保護法（日本）対応状況

| 観点 | 状況 |
|------|------|
| 取得する個人情報の最小化 | ✅ お名前と挙式日のみ（必要最小限） |
| 安全管理措置 | ✅ Google社のセキュリティ基盤利用 |
| 第三者提供 | ✅ Anthropic社にメッセージ生成依頼時、必要なテキストのみ送信 |

## 📚 用語集

| 用語 | 意味 |
|------|------|
| **HTTPS** | 通信を暗号化する標準プロトコル。盗聴を防ぐ |

| **OWASP Top 10** | 世界的なWeb脆弱性ランキング・実質的な国際基準 |
| **PropertiesService** | GASが提供する暗号化保管庫（APIキー保管に使用） |
